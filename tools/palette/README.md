# tools/palette — idle 底色配色体检

改 `src/musicflow-remote-card.js` 里的 `IDLE_GROUPS` 之后，跑一遍这个工具，确认配色环的不变量还成立。

**唯一数据源是源码**：工具直接解析 `src/musicflow-remote-card.js` 的 `IDLE_GROUPS`，这里没有第二份配色表，不用同步。

```bash
node tools/palette/check.cjs          # 体检
node tools/palette/check.cjs --order  # 体检 + 打印建议的环顺序
```

## 输出怎么看

| 段 | 含义 |
| --- | --- |
| `逐组` | 每组的相对亮度 `Y`、Lab 的 `L*`/`C*`/色相角 `h`，组内两端 `c1→c2` 的 ΔE，以及**白字落在 c1 上的对比度**（`< 4.5:1` 会标 `跌破 AA`） |
| `最像的 8 对` | 全局两两 ΔE 最小的几对。`ΔE < 20` 偏像、`20~30` 勉强分得开、`> 40` 是明确不同色、`> 60` 是强跳变 |
| `当前环顺序` | 源码里 `IDLE_GROUPS` 的排列，逐段给出相邻 ΔE 和 `ΔY`。**这是最该看的一段** |
| `--order` | 用随机重启爬山 + 交换邻域（固定种子，结果可复现）求 `max-min 相邻 ΔE` 的最优环，打印建议顺序 |

## 必须守住的不变量

1. **环上相邻两组的最小 ΔE 要够大** —— 本项目基线 **65.7**，别低于 ~40，否则换色会"糊"。
   工具会在结尾直接判定（`环很干净` / `可用` / `偏弱`）。
2. **相邻两组最好同时差在亮度上**（`ΔY` 不为 0）—— 这样每换一组吃到"换色 + 换明暗"两重变化，
   呼吸感才立得住。但若 `ΔE` 已经很大（>60），`ΔY=0` 也可以接受（例如 青绿↔橙、暖褐↔藤紫）。
3. **最亮那组的 `Y` 上限 ≈0.183** —— 再亮，白字对比度就跌破 WCAG AA 4.5:1。
   亮度的档位是 `峰 .175 / .140 / .110 / .085 / 谷 .070`，峰值→谷底 **1.88×**。
4. **每组 `Y` 落在既定档位上**，不要随手取一个中间值 —— 档位是拉开呼吸感的设计基线。

## 为什么用 Lab ΔE\*ab 而不是色相差

低彩度色（`C*` 只有 20 出头）的色相必须拉开很大才分得开，而高彩度色差 30° 就已经很不一样。
"两组看着像不像"只有 ΔE 这个感知距离说得准。本项目踩过的坑：初版 12 组里「松墨 vs 青绿」
色相看着差得远，ΔE 却只有 15~17 —— 因为两者都是低彩度深青绿。

> 判「底色 `c1` 定在哪个亮度」用的是 **WCAG 相对亮度 `Y`**（`0.2126R + 0.7152G + 0.0722B`，sRGB 线性化后），
> 不是 HSL 的 `L`，也不是 Lab 的 `L*`。工具里 `Y` 和 `L*` 两列都打了，别混用。
