# MusicFlow Remote Card

一个 Lovelace 卡片，作为 [MusicFlow](https://github.com/ray5378/MusicFlow)
服务端的**完整外部控制器**。

卡片**直连** MusicFlow 后端的实时 WebSocket（`/ws`）与 REST API，与 Web 界面、
移动 App 平级：卡片上的任何操作都会通过同一条通道推送给所有其他客户端，
其他客户端的变化也会立刻反映到卡片上。

> 英文文档见 [README.en.md](README.en.md).

## 功能

- **输出切换** - 实时切换播放器 / 播放组（peer）。
- **播放控制** - 播放/暂停、上一首/下一首、停止、随机/循环模式。
- **进度条** - 平滑插值显示实时进度，支持拖动跳转。
- **歌词** - 同步歌词滚动高亮，固定 3 行窗口、当前行居中（黄色）。
- **队列** - 查看、跳转、删除、拖拽重排。
- **搜索** - 搜索曲库并播放或入队。
- **加入歌单** - 把当前歌曲或搜索结果加入指定歌单。
- **喜欢** - 收藏 / 取消收藏当前歌曲。
- **媒体库** - 浏览歌单 / 专辑 / 艺术家 / 流派 / 我喜欢的音乐，大曲库走服务端分页。

## 混合传输（局域网直连 + 外网代理）

卡片默认**直连** MusicFlow 后端（WebSocket + REST），局域网内延迟最低。
当浏览器无法直连后端时（外网访问、或受 Private Network Access / 混合内容 /
私有 IP 不可路由拦截），卡片会自动切换为**经 Home Assistant 中转**：

- REST 请求走集成提供的代理视图；
- 实时事件由集成通过 WebSocket 订阅转发；
- 封面经 HA **带鉴权拉取**后以 blob 渲染（所以外网也能正常显示封面）。

这需要集成 **1.3.0 及以上**（当前稳定 **1.3.6**）。代理模式下后端 API Key
只保存在 HA 侧，不会下发到浏览器。

直连模式下，后端仍需在 `CORS_ORIGINS` 中放行 HA 前端来源（或设 `CORS_ORIGINS=*`）。

## 封面性能（服务端 v1.1.19+）

- **直连模式**：卡片以缩略图尺寸（约 160px）请求封面，使用可缓存直链；
  服务端按需缩放（sharp），客户端支持时返回 `webp`，并带 `Cache-Control`/`ETag`，
  浏览器跨翻页、跨刷新可复用（304），外网不再重复下载原图。
- **代理模式**：封面经 HA 用集成凭据拉取，卡片内按 `(coverId, size)` 缓存，
  不会用裸 `<img src>` 去打受保护的 HA 端点（那会被 401）。

## 安装

### HACS（推荐）

1. HACS 右上角 ⋮ → **自定义存储库**；
2. 添加 `https://github.com/ray5378/hass-musicflow-card`，类别选 **Dashboard**
   （HACS UI 下拉里没有 "Lovelace"，前端卡片的类别就是 Dashboard）；
3. 进入 **HACS → 前端**，在 **MusicFlow Card** 条目上点**下载**，刷新仪表盘（或重启 HA）。

### 手动

1. 把 `dist/hass-musicflow-card.js` 复制到你的 `config/www/` 目录；
2. **设置 → 仪表盘 → ⋮ → 资源**里添加：`/local/hass-musicflow-card.js`，类型 **JavaScript 模块**。

## 配置

手动添加卡片，类型 `custom:hass-musicflow-card`：

```yaml
type: custom:hass-musicflow-card
```

卡片会自动从 MusicFlow 集成获取后端地址与 API Key。也可以显式指定：

```yaml
type: custom:hass-musicflow-card
url: http://musicflow.local:46400
api_key: YOUR_LONG_LIVED_API_KEY
```

### 固定到指定播放器

设置 `entity` 为 MusicFlow 的 `media_player` 实体，卡片读取该实体的
`peer_id` 属性并默认选中对应输出：

```yaml
type: custom:hass-musicflow-card
entity: media_player.hivi_h5mkii_2
```

只有 MusicFlow 创建的实体带 `peer_id` 属性；非 MusicFlow 的 media_player
该配置无效，卡片回退到第一个可用输出。

### 传输模式

默认 `auto`：先探测直连，失败且集成支持时自动切换 HA 代理。也可强制指定：

```yaml
type: custom:hass-musicflow-card
transport: direct   # 始终直连后端
# transport: proxy  # 始终经 HA 中转（需要集成 1.3.0+）
```

### 未播放态底色（idle ambient）

当前播放器**没有封面可显示**时（停止 / 清空队列 / 无媒体），卡片改用「12 组固定配色轮换」的底色填充，避免整卡失去颜色。有封面时一律沿用封面主色，两者互斥。

实现是 **N 层整卡对角渐变、原地交叉淡入**：每层一条 `linear-gradient(140deg, c1, c2 62%, #14182a 100%)`，初始 `opacity: 0`，各自跑同一条关键帧，靠**负 `animation-delay`** 把 N 层相位均匀错开 1/N 周期。

关键帧的窗口宽度**随层数推导**（不写死）：停留窗 = 淡出窗 = `50/N %`，于是每层的「出现窗」正好等于错峰 `100/N %` —— 保证任意时刻只有相邻两层在交叉，不会三、四层糊在一起。N=12 时实际注入的是：

```css
@keyframes mf-cyc {                       /* N=12:停留窗 = 淡出窗 = 50/12 ≈ 4.167% */
  0%, 4.167%      { opacity: 1; }         /* 全亮停留 */
  8.333%, 95.833% { opacity: 0; }         /* 淡出，长时间全透 */
  100%            { opacity: 1; }         /* 淡入回来 */
}
```

> N=5 时上式正好算回旧版的 `{0%,10%→1; 20%,90%→0; 100%→1}`，所以视觉基准没变。**关键帧不写死在 CSS 里**，而是由卡片在挂载后按 `50/N` 注入 —— 写死窗口只对某一种层数成立，层数一多错峰小于窗口，就会有 3~4 层同时半透明、主导配色权重掉到约 45%，观感发糊。

各层相位均匀错开 1/N 周期（N = 配色组数，现 **12 组**）——交叉区里必然一层在升、另一层在降，所以既没有「先暗再亮」的空档，也不会叠加变亮（每层都是**全不透明**渐变，`over` 合成会自动归一）。唯一要留意的是**底层漏出**：所有层都半透时会透出卡片底色。实测最大漏出 **N=5 → 25%**，**N=8 → 1.56%**，**N=12 → 0%**（错峰 8.33% 已比停留窗还密，任意时刻都有一层满不透明压在最下面）。全程只动 `opacity`（合成属性）——**无位移、无重绘、无滤镜，主线程零参与**。

> 2.3.0 用的是「5 格雪碧条 + `background-position` 平移」，过渡是相邻两格的空间线性插值，底色会跟着「往左走」而不是原地换色；**2.3.1 起改为 A+ 方案的原地交叉淡入**。

```yaml
type: custom:hass-musicflow-card
idle_background: true    # 默认 true;设 false 关闭(回到无封面的静态紫灰渐变)
idle_speed: normal       # slow | normal | fast | off(纯静态,停在首组＝深红)
idle_theme: auto         # 只影响强调色(图标/进度条),不再影响底色
```

- **12 组固定配色**（以**深红**为起点）：**深红 / 青绿 / 焦橙 / 湖青 / 暗金 / 靛蓝 / 暖褐 / 藤紫 / 松墨 / 品红 / 草绿 / 烟灰**，写死在卡片里，不随主题变化。
- **顺序是固定的环，不随机**：代码里没有任何随机数，永远按上面这个顺序循环，末组接回首组。环的顺序用 **Lab ΔE 直接优化**（max-min 判据），最终**相邻两组的最小 ΔE = 65.7** —— 每换一组都是一次肉眼明确的跳变（ΔE 65 约等于「中蓝 → 中橙」的差距）。
- **起点只决定「首屏色」**：环是循环的，旋转起点**不改变任何一段相邻 ΔE**（Σ 也恒定不变），只决定首次进入 idle 态时先看到哪个颜色。起点取深红，是因为它是这条环上彩度最高、色相最正的暖色，开场辨识度最高。想换首屏色只需旋转 `IDLE_GROUPS` 的起点，不必重跑环序优化。
- 判「两组看着像不像」的口径是 **Lab ΔE\*ab，不是色相差**：低彩度的深青绿必须拉开很大色相才分得开。初版 12 组里「松墨 vs 青绿」只有 ΔE 15~17，于是把松墨挪到 125°（真·墨绿）、青绿提彩度到 65% 并挪到 170°、暖褐降饱和 —— 三者最近邻距离由 15/20/21 拉到 27/27/24。全表最像的一对是「暖褐 vs 焦橙」（ΔE 24.4），它们在环上不相邻。
- 每组按**相对亮度 Y** 定标（不是 HSL 的 L）：`峰 0.175`（草绿 / 湖青 / 靛蓝）/ `0.140`（品红 / 青绿 / 焦橙 / 暗金）/ `0.110`（深红 / 暖褐 / 藤紫）/ `0.085`（烟灰）/ `谷 0.070`（松墨），峰值到谷底 **1.88×**。相邻两组都同时吃到「换色 + 换明暗」两重变化，观感上的「呼吸」才立得住。
- 深红 / 焦橙 / 暗金 受「暗底 + 白字」约束（相对亮度上限 ≈0.183，再亮白字对比度就跌破 WCAG AA），只能压到这个深度，不是明亮原色 —— 这是取舍，不是取色失误。
- 烟灰是唯一的**无彩**组（饱和度 ≈7%），补的是「色相之外的那条轴」，夹在两张高彩之间当一次换气。
- `idle_speed` 缩放「每组停留秒数」：`slow` 11.2s / `normal` 7s / `fast` 4.2s，一轮分别是 89.6s / 56s / 33.6s；`off` 静止在首组（深红）。
- `idle_theme` 现在**只**决定强调色（图标 / 进度条 / 选中态）的色相：`auto`（默认）取 HA 主题 `--primary-color` 派生；也可固定 `twilight` / `ocean` / `ember` / `forest` / `mono`。
- 底色是固定深色渐变（收尾 `#14182a`），所以 idle 态一律按「暗底浅字」渲染，不再随 HA 明暗模式切浅色底；白字落在最亮的峰值组上对比度仍有 **4.67:1**（过 AA）。
- 卡片滚出视口、切到后台标签页时自动停表；**打开队列 / 媒体库面板时不停表** —— 那个面板是透明全屏覆盖，底下露出的正是这层流动底色，继续轮换才自然（停住会看着像卡死）；系统开启"减少动态效果"时降级为静态底色（停在首组＝深红）。

## 国际化（i18n）

卡片面向用户文案全部接入本地化，**完全跟随 HA 系统语言**自动切换（`zh*` 显示中文，其余显示英文），不提供手动切换入口：

- **基础设施** `src/localize/localize.js`：`_loc()` 读取 `hass.language`，缺 key 先回退中文再回显 key；HA 切换语言时自动重建 localizer。
- **语言包** `src/localize/languages/zh.js` / `en.js`：62 键一一对齐；构建产物 `dist/hass-musicflow-card.js` 已含本地化逻辑（无 `localStorage` 覆盖）。
- **新增要求**：任何新用户可见文案必须同时补 zh.js 与 en.js，键集合一致，禁止硬编码中文。
