# v2.8.21 — 拖动音量后打开流转页，整张卡片空白且无法操作

> 主理人实机反馈：**拖动音量滑块之后，再打开「流转播放」页，整张卡片不显示任何实际
> 内容，任何操作都点不动。**

这是本卡片目前为止唯一一个**整卡级**故障：不是某个面板显示错，而是渲染直接崩掉。

## 根因（真实 Chrome 实测，非推测）

把 v2.8.20 产物放进真实 Chrome、按「开音量面板 → 拖滑块 → 打开流转页」操作，控制台
直接抛出：

```
TypeError: Cannot set properties of null (setting 'data')
    at ChildPart._          (lit-html)
    at ChildPart._$AI       (lit-html)
    at TemplateInstance._update
    at MusicFlowRemoteCard.update
```

打开 dev 版 Lit 复跑，报错把原因讲得更直白：

```
This `ChildPart` has no `parentNode` ... setting the element's `innerHTML`
or `textContent` can do this.
```

链路上只有一处这么干 —— `_volPointerMove()` 为让数值跟手而**直改 DOM**：

```js
val.textContent = Math.round(pct) + "%";   // ← 元凶
```

`.vol-value` 的内容原本是 Lit 的文本绑定 `${vpct}%`，Lit 在它前面插了自己的 part
标记节点；`textContent` 赋值会把**标记节点连同文本一起抹掉**。此后任意一次
`requestUpdate()`（打开流转页、切歌、一次状态推送……）走到这个 part 时
`startNode.nextSibling` 已是 null，`node.data = value` 当场抛错 → Lit 渲染中断 →
整张卡片停在空白状态，且后续所有交互都失效。

也就是说：**拖一次音量，卡片就已经"死"了**，打开流转页只是第一个把它暴露出来的动作。

## 修法

数值不再走文本子节点，改由**属性**承载、CSS 渲染，属性赋值不会动到 DOM 结构：

- 模板：`<span class="vol-value" style="left:${vpct}%" data-v="${vpct}%"></span>`；
- CSS：`.vol-value::before { content: attr(data-v); }`；
- 拖动：`val.setAttribute("data-v", ...)`（只写 style / attribute）。

数值跟手的手感完全不变（实测拖动后 `data-v=90%`、`::before` 渲染出 `90%`），
但 Lit 的 part 标记再也不会被碰掉。代码里两处都加了 🔴 注解，写明「此处禁止
`textContent` / `innerHTML`」，避免以后有人为跟手再抄一次这个写法。

## 复验（无头 Chrome，关动画量最终态）

| 场景 | 拖动后 | 打开流转页后 |
|---|---|---|
| A 不拖音量直接打开（对照） | — | `.panel.transfer` 可见，`.tp-peer` 可见 3 个 |
| B 拖动后抬手 → 打开 | `data-v=90%`，无异常 | 可见，3 个 |
| C 拖动中不抬手 → 打开 | `data-v=90%`，无异常 | 可见，3 个 |
| D 拖动 → 关音量面板 → 打开 | `data-v=90%`，无异常 | 可见，3 个 |

修复前的 B/C/D 三档全部抛 `TypeError`、卡片空白。
