# v2.8.26 — 进度条不再「往前走时轻微后跳」；外推门口径修正

> 反馈：进度条在正常前进时会突然往回跳一小格（客户端、HA 卡片、Web 卡片同构，三端一起修）。

## 修一：进度回写加 0.5s 单向防抖

服务端 `position` 只报到 0.1s 精度，卡片每 2s 轮询一次重新对齐本地时钟。截断误差 + 网络往返
会让外推值有时比本地已经推进的值**小 0.1~0.3s**，写回即「往前走时后跳一小格」。

新增 `_adoptProjectedPosition(projected, local, sameSong, toleranceSec = 0.5)`：

- 同曲内、且服务端值比本地小 0~0.5s → **保留本地值**（吞掉精度抖动）；
- 前进 / 大回退（真 seek）/ 换歌（`sameSong=false`）→ 一律采纳服务端值；
- seek 由原有的 `stale` / `seekDragging` 守卫在前挡住，不经过这里。

## 修二：外推门改为 `statePlaying || advancing`

| 口径 | 问题 |
|---|---|
| 裸 `statePlaying` | 设备 GENA 缓存把 state 错报成 STOPPED/PAUSED，而 SOAP 的 position 真实在前进（240 实测 2 小时：HiVi 8 次、纯AP组 15 次）。外推被关掉后，采样年龄 `ageSec` 会原样变成进度后跳。 |
| `this._ui.isPlaying` | 它表达「按钮在播」，含 BUFFERING。切歌/seek 后服务端报 BUFFERING 2~5s，期间 position 是**刻意冻结**的，对冻结值外推会让 projected 虚涨，PLAYING 到达那一刻整体回跳。 |
| `statePlaying \|\| advancing` ✅ | `advancing` 的定义就是「position 相比上一拍真实前进」== 「值没被冻结」，冻结时门自动关上，无需再单独判 BUFFERING。 |

## 实测口径

240 / v4.15.11 / 2026-11-27 12:00–13:59，4322 条 status 采样：

- 设备型 peer（HiVi / iEAST / 纯AP组）采样年龄 `ageSec` 中位 -0.002~-0.010、**max 0.000、>0.5s 零次**；
- 进度斜率 `Δposition/Δ真实时间` 中位 0.986~0.993。

即：服务端每次 SOAP 查询都会刷新 `updatedAt`，外推量≈0，v2.8.24 那套「2s 滞后」当前不存在 ——
外推现在是安全网，守的是「服务端 updatedAt 变旧 / 跨机时钟偏差 / GENA 时间戳更旧」那类边界。

## 测试与守卫

- vitest **347 全过**，新增双向用例：错报 STOPPED + position 前进 → 外推生效（10.0 + 3s → 13.0）；
  BUFFERING + position 冻结 → 不外推（保持 10.0）。
- 守卫 `guard-client-link` **20/20**：正向钉住 `const extrapolate = statePlaying || advancing`，
  反向禁止退回裸 `statePlaying` / `_ui.isPlaying`，并在源码里留了带实测数据的勿删长注释。
- 顺带修正 `guard-seek-contract` 的预存误判：dist 压缩后是 `seekDragging)return`，
  旧正则 `/seekDragging\|\|/` 永远匹配不到（CI 先 build 再跑守卫，会卡发版）。
