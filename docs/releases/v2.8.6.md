## MusicFlow 卡片 v2.8.6 — 直连支持「仅用户名 + 密码」登录，切换静默无提示

v2.8.5 把默认传输恢复为 auto 后，发现一处遗留缺陷：当卡片只配置了**用户名 + 密码**
（无静态 API Key、也无现成 JWT）时，直连可达性探测会被提前 `return false` 短路，
导致 auto 模式误判「直连不可达」而回落 HA 中转，即使局域网内其实可以直连。
本版修复，并明确切换连接方式全程静默、不弹提示。

### 变更：探测前允许以用户名/密码登录拿 JWT

- `BackendClient._probeDirect()`：放宽前置守卫——仅当 `url` 缺失，或「既无 token/apiKey、
  又无 username/password」时才返回 false；否则先调用 `_ensureToken({ forProbe: true })`
  以用户名/密码登录换 JWT，再探测直连可达性。
- `BackendClient._ensureToken(opts)`：新增 `forProbe` 选项。`proxy` 模式下默认仍不登录
  （由 HA 集成代理鉴权），但探测直连可达性（`forProbe: true`）时允许登录，从而让
  中转 → 直连的回切（`_startProxyRecheck`）也能在「仅用户名/密码」场景下生效。
- **切换静默**：直连 ↔ 中转 的探测、回切、兜底只写 console 调试日志（`log/warn`），
  不触发任何 UI 提示、通知或弹窗（满足「切换连接方式不需要提示」）。

### 安全

- 代理 REST 分支（`rest()` 的 proxy 路径）走 `hass.fetchWithAuth` 且从不在请求里附带
  卡片自身的 JWT；`_wsUrl` / 直连 `rest` 仅在 `mode === "direct"` 时使用卡片 JWT，
  因此「探测时登录获取的 JWT」不会泄漏到中转请求中。

### 测试

- 新增单测：仅用户名/密码（无 apiKey）时 `_probeDirect` 先登录再探测并返回 true；
  登录网络失败时被捕获返回 false 不抛错；`forProbe` 在 proxy 模式下仍能登录探测直连。
- 全量 `npx vitest run` 通过；构建 `npm run build` 产出 `dist/hass-musicflow-card.js` 与源码一致。
