# v2.8.22 — 极简模式「操作后左右留白被吃掉」根治

> 主理人实机反馈：极简模式下，打开 HA 页面不做任何操作时歌词/封面的左右间隔正常；
> **只要做过任意操作再进入极简，内容就往左右边缘移动（贴边）**。v2.8.16 修过一次没修干净。

## 根因（本机真实 Chrome + CDP 真实鼠标事件实测）

**CSS 类名撞车**：`.wrap` 进入极简模式时加的状态类叫 `mini`（render 里 `${u.mini ? "mini" : ""}`），
而小按钮（队列/媒体库列表里的 ▶ ✕ 等）的样式也写成裸选择器 `.mini`。`.wrap.mini` 双类特异性高于
`.wrap`，而小按钮那套样式里的 `border / background / color / border-radius / font-size / cursor`
在 `.wrap.mini` 里都没声明 —— **全部漏给了整张卡**。

致命的一条是：

```css
.mini:hover { transform: scale(1.06); }   /* :active 是 scale(0.94) */
```

极简态下**整张卡**随指针悬停放大 6%、按下缩小 6%。这精确解释了两条路径的差异：

| 场景 | `.now` 距 ha-card 左/右（修复前） |
|---|---|
| 打开页面不动（指针不在卡上 → 无 hover） | 15.00 / 15.00（正常） |
| 操作后（指针停在卡上 → hover 生效） | **2.10 / 2.10（贴边）** |
| 鼠标按下（:active 生效） | 27.90 / 27.90 |
| 完整模式基线 | 14.00 / 14.00 |

同时 `.wrap` 还被改写了 `background`（rgba(0,0,0,0.06)）、`color`、`radius=8px`、`font-size=12px`、
`cursor=pointer`，并被 1px 边框吃掉 2px 宽度（clientWidth 460→458）。

也解释了 v2.8.16：当时 `.mini{padding:3px 8px}` 漏给 `.wrap` 把纵向 padding 压成 3px，
v2.8.16 用 `padding:14px` 把**这一条**盖住了，其余漏掉的样式（含 hover 放大）一直在。

## 修法

所有小按钮样式限定为 `button.mini`（已核实源码 12 处 `.mini` 全是 `<button>`，`.wrap` 是 div，
从此不可能再命中）：`.mini` → `button.mini`、`.mini:hover` → `button.mini:hover`、
`.mini:active` → `button.mini:active`、`.mini.imp` / `.mini.imp:disabled` 同步限定。
另加一条**源码守卫测试**（tests/card.test.js）：禁止再出现任何裸 `.mini` 选择器。

## 复验（本机无头 Chrome，真实计时路径进入极简）

修复后 A/B/C/D 四态与完整模式基线**逐位一致**：`.now` 左右留白全部 14.00、宽 432.00；
`.wrap` transform=none、border=0、clientWidth=460、background 透明；小按钮自身样式
（border/radius/bg/color/font/padding/cursor）与修复前完全一致，未误伤。

门禁：`npx vitest run` = **336 passed**（基线 335 + 新增守卫 1 条）；client-link / UI 契约 /
seek 契约 / 版本守卫四道全绿。
