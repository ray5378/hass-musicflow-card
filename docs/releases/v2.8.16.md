# v2.8.16 — 极简模式「两种位置状态」根治

> 主理人实机反馈：极简模式下歌词/封面有**两种位置** —— 打开页面自动进入是对的，
> 点击/选择过之后再进入就「左右和上面贴着卡片边缘」。

## 根因（无头 Chrome 实测，非推测）

把卡片放进真实 Chrome 渲染、关掉过渡动画量最终态，测到两条硬伤：

| | 完整模式 | 极简模式（v2.8.15） |
|---|---|---|
| `.wrap` 上下 padding | 14px | **3px**（被吃掉 11px） |
| 卡片高度 | 269px | **249px**（矮 20px） |
| 内容上移后 `.now` 顶部 | 73px | **4px**（应为 14px） |
| `--mini-shift` DOM 值 | 28px（滞后一帧） | 59px |

1. **padding 被浏览器吃掉**：切换器行用 `translateY(-200%)` 向上移出，会溢出到容器的
   block-start 之外；Chrome 因此把 `.wrap` 的 padding-top/bottom 从 **14px 压到 3px**。
   于是整卡矮 20px、所有内容整体上移 11px —— 歌词盒再跟着上移 59px，顶部就顶到卡片
   边缘、「贴边」。这就是用户看到的画面。
2. **上移量滞后一帧且是近似值**：`--mini-shift` 用 `offsetHeight + 硬编码 12px gap` 算，
   而且只在「非 mini」时测。测量发生在渲染之后，写进 DOM 要等下一次渲染 —— 不同的进入
   路径拿到的值不同，于是**同一个极简模式出现两种位置**。

## 修法

- **`.wrap.mini` 显式锁死 `padding: 14px`**（与完整模式同值）：padding 不再漂移，卡片高度
  与上移基准都稳定（实测 269 → 271，2px 是取整误差，原来差 20px）。
- **上移量改测静态布局差**：`_measureMiniShift()` 取 `.now.offsetTop − .outputs.offsetTop`。
  - `offsetTop` 是布局位置，**不受正在播放的 transform 影响** ⇒ 极简进行中也测得准；
  - 自动包含 gap、warnbar 等一切布局因素，不再有硬编码的 12px；
  - **每次渲染都刷新**（不再限「非 mini 才测」），值变化时补一次渲染写进 `--mini-shift`
    ⇒ 不存在「上一次进入留下的旧值」，两条路径必然一致。
- 保留 64px 兜底（DOM 未就绪时不至于上移 0）。

实测复验（关动画量最终态）：

```
完整模式  padTop=14px wrapH=269 nowTop=73.0 outputsTop=14.0
A 自动进入 padTop=14px wrapH=271 nowTop=15.0 outputsTop=-79.0
B1/B3      padTop=14px wrapH=271 nowTop=15.0 outputsTop=-79.0   ← 与 A 完全一致
```

`.now` 上移后顶部 15px ≈ 切换器行原来的 14px —— 歌词/封面正好落在腾出的位置，不再顶边。

## 校验

- 测试 **324 → 331 全绿**：3 条行为测试（offsetTop 差值、布局变化跟上、测不到时保兜底）
  + 4 条静态守卫（padding 锁死、用 offsetTop 不用 rect、测量接线、兜底 64）。
- **负向验证**：把 `padding: 14px` 从 `.wrap.mini` 摘掉，守卫立即 FAIL，恢复即绿。
