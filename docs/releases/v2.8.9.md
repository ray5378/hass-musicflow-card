# v2.8.9

**类型**: 修复（手机端播放控件圆形按钮被压成椭圆）

## 问题
卡片在手机端（窄屏）显示时，底部播放控件那一排的圆形按钮被压成椭圆。

## 根因
播放控件行 `.controls` 是 flex 容器，`.ctl` 是它的 flex item：

```css
.controls { gap: 23px; }                                  /* 旧 */
.ctl { width: 42px; height: 42px; border-radius: 50%; }   /* 旧 */
```

`.ctl` 默认 `flex-shrink: 1`，可用宽度不足时 flex **只压缩主轴宽度、交叉轴高度仍为 42px**
⇒ `border-radius: 50%` 作用在 非正方形 上 ⇒ 正圆变椭圆。

该行 7 个按钮的自然宽度 = `7 × 42 + 6 × 23 = 432px`，窄于 432px 的卡片就会开始变形。

## 修复
```css
.controls { width: min(100%, 432px); align-self: center; justify-content: space-between; gap: 0; }
.controls > .ctl { flex: 0 1 42px; min-width: 0; height: auto; aspect-ratio: 1; }
```

- **`aspect-ratio: 1` + `height: auto`** 是核心：宽度被压缩时高度同步跟随，始终保持正方形 ⇒
  `border-radius: 50%` 恒为正圆。
- **不是简单加 `flex: 0 0 auto`**：那只会禁止收缩，极窄卡会横向溢出。这里分两级自适应 ——
  432px→294px 由 `space-between` 先把 6 个间距从 23px 平滑收紧到 0；窄于 294px 后 7 个按钮再等比缩小。
- `min-width: 0` 让 shrink 真正生效（button 默认 `min-width: auto` 会以图标为下限拒绝收缩）。
- 覆盖块选择器 `.controls > .ctl` 与 `.ctl.play` 特异性相同（0,2,0），因此**必须写在 `.ctl.play` 之后**
  才能接管 play 键 —— 已加静态守卫钉死这个顺序。
- 仅作用于播放控件行；音量面板里的 `.ctl` 保持原 42px。

## 验证（Chrome headless 实测 `getBoundingClientRect`，非纸面推理）
| 可用宽度 | 按钮实测尺寸 | 间距 |
|---|---|---|
| 480 / 432px | 42 × 42 | 23.00px（与改前一致，零回归） |
| 380px | 42 × 42 | 14.33px（先收间距） |
| 280px | 40.0 × 40.0 | 0 |
| 240px | 34.3 × 34.3 | 0 |
| 200px | 28.6 × 28.6 | 0 |

宽高始终严格相等 ⇒ 恒为正圆。改前同场景实测为 **34.6 宽 × 42 高**（即椭圆），已消除。
图标在所有档位恒为 20×20 / 22×22，未被放大。

## 测试
- 292 → **297 用例全绿**（新增 5 个静态守卫用例，`tests/card.test.js`）：
  1. 覆盖块含 `flex: 0 1 42px` / `min-width: 0` / `height: auto` / `aspect-ratio: 1`
  2. **级联顺序钉死**：`.controls > .ctl {` 必须晚于 `.ctl.play {`，且之后不得再出现给 `.ctl` 钉固定高度的规则
  3. `.controls` 含 `min(100%, 432px)` / `space-between` / `align-self: center` / `gap: 0`，并断言 `(432-7*42)/6 === 23`
  4. svg 只放宽 `max-*`，不放大原始尺寸
  5. dist 与 src 同步
- **负向验证**：把覆盖块搬到 `.ctl.play` 之前模拟「有人重排 CSS」⇒ 只有级联守卫 FAIL，证明守卫能捕获静默回退。

## 兼容性
- 纯样式改动，不涉及传输 / 鉴权 / 播放逻辑。
- 悬停 / 按下的 scale 与阴影、`.ctl.active` 与 `.ctl.like.on` 的 accent 变色语义均未改。
