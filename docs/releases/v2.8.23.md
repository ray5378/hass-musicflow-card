# v2.8.23 — HA 2026.11 兼容：卡片重挂载不再「冻住」数据；群组当前曲改由队列推导

> 主理人反馈：升级 HAOS 2026.11（Core 2026.11.0 / Supervisor 2026.10.5 / OS 18.4 / Frontend 20261028.4）后，
> 「全屋」群组卡片上的封面 / 歌词 / 歌曲信息**间歇性不显示，或显示的不是当前播放那首**。

## 根因一：前端 2026.11 更频繁地 detach/attach 卡片元素，而卡片重挂载只接了一半

HA 前端在 2026.11 把 hass 改为 **setter 直接下发**（frontend PR #55149 `Forward hass to the card from a setter instead of the update cycle`），
并对「元素被移除后不要留下订阅 / 定时器」做了一轮系统性清理（#55056 / #55055）。结果是卡片元素在
**卡片重建、面板切换、条件可见性翻转**时被 detach 再 attach 的频率明显上升。

而本卡片的卸载路径是完整的、挂载路径却缺了一半：

| 生命周期 | 实际行为 |
|---|---|
| `disconnectedCallback → _teardown()` | 清掉 2s 轮询 `_pollTimer`、250ms tick `_tickTimer`、15s 可达性探测 `_probeTimer`、`visibilitychange` 监听、心跳、封面观察器 |
| `connectedCallback`（旧代码） | **只做 `_client.connect()`** —— 上面这些一个都没补回来 |

于是卡片一旦被 detach 再 attach：WS 事件还在（播放进度照走），**但 2s 轮询与前台恢复刷新永久停摆**。
群组的当前曲本来就依赖轮询/事件去更新，now-playing 就停在重新挂载前的那首歌
—— 正是「能显示，但不是当前播放那首」的表现。

**修法**：把运行时接线收敛成幂等的 `_armRuntime()`（探测定时器 / `visibilitychange` / `_ensureTracking()` / 立即
`_refreshCurrentPeerView()` 一次），bootstrap 与每次重新 attach 都走同一条路；重挂载后立刻拉一次权威状态，
不等 2s 轮询，首帧就应是当前播放那首。

## 根因二：群组 peer 的 status 不带 media，卡片从没从队列项反推当前曲

实测 `GET /rest/api/v1/peers/group:…/status` 只返回 `state / position / duration / volume / muted / updatedAt`：
**没有 media、没有 items**。而 WS 的 `peer_queue_changed` 走 `summarizeQueue`，>200 首时 `items` 为空，只带 `currentIndex`。

也就是说群组卡片唯一能拿到「当前是哪首」的路径是「可听显示延迟」窗口内的 displayHold —— 窗口一过就停在旧歌，
封面 / 歌词自然跟着旧歌。

**修法**：`_applyQueue` 末尾新增 `_syncSongFromQueue()`：

- 仅当 `status` 不自带 media（`_statusHasMedia === false`）、队列 `isActive`、`currentIndex` 有效时生效；
- 命中 `qCache` 就直接用；未命中则按 `CHUNK` **只补拉 currentIndex 所在块**（只在换曲时一次，稳态 2s 轮询不增加请求）；
- 把 `songId / title / artist / album / coverArt / duration` 写回 now-playing，歌词与封面随之更新。

status 自带 media 的 peer（DLNA / AirPlay / Sendspin）保持原路径，**不会额外多打接口**。
换曲后若拉取期间又换了曲（索引已变）或目标已切走，结果直接丢弃，不会写脏。

## 顺带：断线提示移到歌词区中间

「无法连接后端，自动重连中」原先渲染在标题上方，出现时会把卡片撑高。现在移入歌词视口
（`.lyricbox` 内绝对定位的 `.lyricwarn`，视口固定 100px），提示出现 / 消失**不再改变卡片高度**。
