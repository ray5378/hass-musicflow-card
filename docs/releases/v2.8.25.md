# v2.8.25 — 首页「为你推荐」改接服务端 recommend-section：固定卡零门槛、随机位按小时冻结，老服务端逐字回落

> 背景：Web 首页与 HA 卡片各自在本地拼固定卡和随机位，两边门槛不一样（Web 零门槛 / 卡片 >30 首），
> 随机每次刷新都重洗。服务端新增 `GET /api/v1/home/recommend-section` 一次给全，卡片改为同源取值。

## 改动

- `BackendClient` 新增 `getHomeRecommendSection()`：`GET /api/v1/home/recommend-section`，复用 `rest()` 既有的鉴权、401 续期重试与非 2xx 抛错，写法与 `getPlaylistsV2` 一致。
- `_fetchHomeItems` 阶段一优先走新端点：固定卡在前、随机位在后，**顺序原样**渲染；不再本地洗牌、不再拉 200 条全量歌单。
- **固定卡零门槛**：服务端给几张就渲染几张（10 首的小卡同样展示），曲目数原样带出。原 `>30 首` 门槛只保留在老服务端回落路径里。
- **随机位确定性**：服务端按 `md5(userId|hourBucket|id)` 洗牌并按小时快照冻结，同一小时内多次刷新顺序稳定，不再抖动。
- `degraded=true`（存在指向已删除歌单的固定卡）只打一条 `console.warn` 说明缺哪几张，本轮不做 UI 提示。
- **老服务端回落**：新端点 404 / 网络失败 / 响应形状不对 / 客户端桩根本没有该方法（能力探测）→ 逐字走原有 `getHomeCards` + `getPlaylistsV2(pageSize=200)` + `getHomePlaylistCount` 三路逻辑，`>30` 门槛与本地 `Math.random - 0.5` 洗牌全部保留，绝不渲染空白首页。
- 新增 `_validHomeSection()` 形状校验：`success !== true`、`fixed`/`random` 不是数组、任一项缺 id 一律返回 `null` 走回落，绝不把 HTML 错误页当空 section 渲染。
- 身份字段统一用 `playlistId`（新端点的 `fixed[]` 刻意不返回 `pluginId`），与 `_pushHomePlaylist` 的 id 语义对齐。
- 阶段二（平台精选 / 本地随机）逻辑未动：新增 `_appendHomeSections()` 承载原内联逻辑，逐项字段与顺序保持逐字节一致。

## 已知边界

- 卡片与 Web 首页同源，但 HACS 独立发版：**服务端未升级（无该端点）时仍是老口径**，需服务端 v4.14.9+ 才吃到零门槛固定卡与小时冻结随机。
- 服务端把固定卡指向的歌单删掉时会返回 `degraded=true`，卡片只告警不提示用户，缺行卡显示为空曲目数的歌单行。
