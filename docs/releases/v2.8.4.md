## MusicFlow 卡片 v2.8.4 — 群组成员只允许 AirPlay / Sendspin

### 问题

流转页进入群组管理模式后，**DLNA 设备会显示「加入群组」勾选圈，而 AirPlay 设备反而没有**。点 DLNA 的圈只会换来一次「群组成员更新失败」，真正能进组的 AirPlay 却根本点不到。

### 根因

勾选圈的显隐条件写成了错的 kind 名单：

```js
const showBadge = ... && (p.kind === "dlna" || p.kind === "sendspin");
```

群组出流链路是 `sendspin pump → AirPlay BridgeRing`，只有 **airplay / sendspin** 两种成员有出声通路。服务端自 2026-10-23 起就在 `splitMemberId()` 里只认这两个命名空间，`dlna:` 与裸 id 一律 400 拒收（`…是 DLNA 设备：DLNA 各设备自拉流、没有共享时间线…`）；Web 端群组页的候选列表（`Groups/index.vue` 的 `selectableDevices`）与 240 上的真实数据也都是这个口径 —— 11 个组、20+ 条 `memberIds` 全是 `airplay:<deviceId>` / `sendspin:<clientId>`，没有一条 `dlna:`。

所以卡片的毛病是**双向的**：能加的没有入口，不能加的给了入口且必然失败。

### 修复

- 新增 `_canJoinGroup(p)`：只认 `airplay` / `sendspin`；勾选圈条件改为 `joinable || member`，**已是成员仍渲染** —— 历史组里若存着 DLNA 成员，用户还得有出口把它移出去。加入路径另加一道拒绝（提示「该设备不支持加入群组」，不发请求）。
- 成员键统一为服务端口径的完整 `peerId`（`airplay:<id>` / `sendspin:<clientId>`）。旧实现把 `dlna:` 前缀剥掉再提交，与 `memberIds` 里存的字符串对不上，服务端按 no-op 处理 ⇒ 成员删不掉。新增 `_groupMemberKey` 按「peerId → kind:裸id → 裸id」回查，移除时回传**组里那条**原样字符串。
- 管理态提示条补上限定：`仅 AirPlay / Sendspin 设备可加入`（中英文同步）。

### 服务端现状（本次一并复核，无需改动）

`groupManager` 三条写路径（建组 / `PUT` 全量替换 / `POST members` 增量）都会过 `assertMembersAvailable`，DLNA 与裸 id 一律 400 且组内容不变。已在 240 上逐条实测确认，并为增量接口补了一条单测（此前只有建组与全量替换有覆盖）。

### 测试

- A6 改用 airplay / sendspin 成员夹具，并新增断言：**DLNA 设备在管理态下不得出现勾选圈**；加入调用必须传完整 `sendspin:<clientId>`。
- 新增 A6b：① 直接对 DLNA 调 `_tpToggleMember` 必须被拒且不发请求；② 历史组存裸 id（`d1`）时勾选圈保留，点一下用组里那条 `d1` 删除（不是自己造的 `dlna:d1`）。
- `_memberKeyFor` 断言改为完整 peerId，并覆盖「组内裸 id 优先回查」。
- 单测 289/289，四个守卫脚本（card-ui / client-link / seek-contract / version）全绿。
